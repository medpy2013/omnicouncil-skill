# OmniCouncil

[English](README.md)

**مهارة تُستدعى يدوياً لمراجعة الطلب ونقد المسودة ثم تنفيذ العمل المصرّح به والتحقق منه.** تعمل مع مهام البرمجة والأسئلة العامة، وتختار ملف المرجع المناسب عند الحاجة.

## طريقة العمل

![رسم متحرك يوضح مراحل مراجعة OmniCouncil وتنفيذ المهمة](assets/omnicouncil-flow.gif)

الرسم توضيحي للمراحل. [افتح المخطط الكامل](assets/omnicouncil-process.svg).

### مثال بصري لفحص الادعاءات

![رسم توضيحي لمسودة إجابة تُراجع بمقابل مستندات ومصادر قبل تقديم رد متحفظ](assets/omnicouncil-claim-check.png)

الصورة تشرح فكرة المراجعة فقط؛ ليست نتيجة اختبار ولا دليلاً على خفض الهلوسة بنسبة محددة.

1. **المتخصص:** يحدد المبدأ والأدلة والمجهول المهم.
2. **المهندس:** يطرح مسودة عملية قابلة للفحص.
3. **محامي الشيطان:** يختبر أقوى سبب معقول لفشلها، ولا يخترع عيباً.
4. **المستخدم المتشكك:** يفحص الوضوح والجهد واحتمالات سوء الفهم.
5. **المراجعة:** تُعالج الاعتراضات الصحيحة وتُذكر المخاطر التي لم تُحسم.
6. **المايسترو:** يقدم النتيجة المنقحة، وينفذ العمل المصرح به بأدوات المضيف متى أمكن، ويذكر ما تحقّق منه فعلاً.

تشبيه «الذكاء الاصطناعي كموظف يوافق مديره» **مجاز** لمخاطر مسايرة صياغة المستخدم والثقة الزائدة. النموذج لا يشعر بالخوف ولا ينوي الكذب حرفياً. للتحقق من الادعاءات المهمة، تطلب المهارة تحويلها إلى أسئلة محايدة، ثم فحص المصدر نفسه والبحث عن دليل مخالف، والتحقق من الحسابات والاقتباسات، والتصريح بما بقي مجهولاً. قد يقلل هذا بعض الأخطاء الممكن تجنبها، لكنه لا يوقف الهلوسة ولا يضمن نسبة تحسن. يشرح [`HALLUCINATION-EVALUATION.md`](HALLUCINATION-EVALUATION.md) طريقة قياس الفرق دون اختراع نسبة.

الأدوار وجهات نظر محاكاة من النموذج نفسه، ما لم تُشغّل المنصة وكلاء مستقلين فعلاً. لا تكشف المهارة سلسلة التفكير الداخلية؛ تعرض خلاصة قصيرة للنقد والأدلة. كما أن النقاش ليس بديلاً عن إنجاز المهمة المطلوبة.

## الاستدعاء اليدوي

المهارة **لا يُفترض أن تعمل في كل محادثة**. استدعها صراحةً مثل `$omnicouncil` في Codex، أو `/omnicouncil` في Claude Code، أو قل: **«استخدم OmniCouncil في هذا الطلب»**.

| المنصة | الإعداد | الاستدعاء والحدود |
| --- | --- | --- |
| OpenAI Codex | ثبّت المجلد كاملاً في **~/.codex/skills/omnicouncil/**. | استخدم **$omnicouncil**؛ إعداد Codex يمنع التفعيل الضمني. |
| Claude Code | ثبّتها في **.claude/skills/omnicouncil/**، وأضف **disable-model-invocation: true** في إعداد Claude Code الخاص. | استخدم **/omnicouncil**؛ لا يضبط هذا Claude.ai أو التطبيقات الأخرى. |
| Gemini CLI | ثبّتها بأمر **gemini skills install** وتحقق عبر **/skills list**. | قد يفعّل المهارات تلقائياً عند الصلة؛ للاستدعاء اليدوي الصارم عطّلها أو أرفق الملف عند الطلب فقط. |
| Gemini Apps | ضع التعليمات في Gem وأضف المراجع المختارة إلى Knowledge، أو أرفق الملف لمحادثة واحدة. | اختر Gem يدوياً واكتب شرط الاستدعاء الصريح؛ هذا ليس تثبيت مجلد مهارة في Gemini CLI. |
| ChatGPT | أرفق **SKILL.md** لطلب واحد؛ وإذا كان إنشاء GPT متاحاً لحسابك، ضع التعليمات فيه والمراجع في Knowledge. | التوفر يتغير. أضف شرط الاستدعاء؛ Custom Instructions العامة تؤثر في محادثات أخرى أيضاً. |
| Kimi Code / Agent Mode | يدعم Kimi Code ملفات **SKILL.md**، وفي Agent Mode توجد قائمة Skills واختيار عبر **/**. | قد يختار Kimi المهارة تلقائياً؛ وZIP ليس صيغة استيراد موحدة لكل واجهات Kimi. |
| GLM / Z.ai وDeepSeek | في تطبيق المحادثة استخدم التعليمات المخصصة إن توفرت أو أرفق الملف لكل طلب؛ وفي API استخدم حقل التعليمات الموثق وأرفق المراجع منفصلة. | لا ندّعي وجود مثبت مهارات موحد لواجهات المحادثة. |
| وكلاء السحابة والتطبيقات الأخرى | استخدم طريقة المهارات أو التعليمات أو ملفات المعرفة التي توثقها المنصة. | التوافق والاستدعاء اليدوي يتبعان التطبيق، لا اسم النموذج وحده. |

الـSkill تتبع **التطبيق أو نظام الوكلاء** لا النموذج بمفرده. راجع [دليل التثبيت التفصيلي](INSTALLATION.md)؛ تختلف طريقة تثبيت المهارة وتفعيلها بين واجهات ChatGPT وGemini وKimi وGLM/Z.ai وDeepSeek. لم تُختبر كل منصة أو نموذج.

## الصراحة حول الجودة

خطة التقييم المرفقة ليست تقريراً بأن الاختبارات اجتازت فعلاً على كل منصة. شغّلها وسجّل التطبيق والنموذج والإصدار والتاريخ والنتيجة. فحص الملفات يكشف مشكلات البنية، لكنه لا يثبت أن النموذج سيتبع كل تعليمة. لا تصف المهارة بأنها مضمونة 100% أو أنها تعمل مع كل شيء.
